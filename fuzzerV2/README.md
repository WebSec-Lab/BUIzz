# fuzzerV2

An alternative browser fuzzer for BUIZZ that uses **Selenium WebDriver** instead of Playwright for browser control. It reuses the same scenario files generated by `fuzzer/user_scenario_gen.py` and applies the same OS-level interaction approach.

## Entry Points

| Script | Purpose |
|---|---|
| `fuzzer.py` | Main fuzzer — loads scenarios from `../fuzzer/scenario/` and drives interactions using Selenium |

## Directory Structure

```
fuzzerV2/
├── fuzzer.py               # Main entry point
├── lib/                    # Per-browser execution cores
│   ├── core_common.py      # Shared execution logic (scenario loading, action dispatch, window management)
│   ├── core_chrome.py      # Chrome / Chromium-based launcher (Selenium)
│   ├── core_edge.py        # Edge launcher (Selenium)
│   ├── core_opera.py       # Opera launcher (Selenium)
│   ├── core_brave.py       # Brave launcher (Selenium)
│   ├── core_whale.py       # Whale launcher (Selenium)
│   ├── core_firefox.py     # Firefox launcher (Selenium)
│   └── userinteraction.py  # Mouse and keyboard interaction primitives
├── browser_info/           # Browser executable path configs
├── cve_lib/                # Corpus URL lists per policy
└── profiles/               # Browser user-data profiles (gitignored)
```

## Libraries

| Library | Role |
|---|---|
| **Selenium** (`selenium`) | Browser automation — launches browsers via WebDriver, navigates pages, and manages browser sessions |
| **webdriver-manager** (`webdriver_manager`) | Automatically downloads and manages ChromeDriver / GeckoDriver binaries |
| **pyautogui** | OS-level mouse and keyboard input — moves the cursor, clicks, sends hotkeys at the screen coordinate level |
| **pywinauto** | Windows UI automation — finds browser window handles, brings windows to focus, reads window positions |
| **psutil** | Process management — detects running browser processes, kills stale instances between scenarios |
| **mysql-connector-python** | Database — writes test results (violation reports) to the MySQL `event_entry` table |

## Difference from fuzzer/

| | fuzzer | fuzzerV2 |
|---|---|---|
| Browser control | Playwright (persistent context) | Selenium WebDriver |
| Scenario files | Generates its own via `user_scenario_gen.py` | Reuses `../fuzzer/scenario/` |
| Cookie injection | Via Playwright context API | Via Selenium `execute_script` |

## How It Works

1. `fuzzer.py` loads scenario JSON files from `../fuzzer/scenario/<browser>/<policy>/` (shared with the main fuzzer).
2. The target browser is launched via Selenium WebDriver through `lib/core_<browser>.py`, which configures the appropriate ChromeDriver or GeckoDriver.
3. User interactions are replayed using the same pyautogui and pywinauto OS-level primitives as the main fuzzer.
4. Detected security policy violations are written to the same MySQL `event_entry` table.
